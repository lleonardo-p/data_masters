# ADR-003: Escolha da Solução para Ingestão e Processamento Batch

- **Status:** Aceito
- **Data:** 2026-07-04
- **Decisores:** Leonardo Lucas Pereira

---

## Contexto

O BAIP necessita realizar a ingestão periódica de dados provenientes de diferentes APIs públicas, além de executar transformações e enriquecimentos para construção das camadas Bronze, Silver e Gold do Data Lake.

A solução deve suportar:

- extração de dados de APIs REST;
- processamento distribuído;
- transformação em larga escala;
- integração nativa com Amazon S3;
- execução agendada;
- escalabilidade;
- baixo esforço operacional.

Foram consideradas as seguintes alternativas:

- AWS Glue
- AWS Lambda
- Amazon EMR
- Apache Airflow + Spark
- Amazon ECS/Fargate

---

## Decisão

Será utilizado **AWS Glue** como plataforma de processamento batch da solução.

Todos os processos de ingestão, transformação e geração das camadas Bronze, Silver e Gold serão implementados através de **AWS Glue Spark Jobs**.

Cada etapa será responsável por uma camada específica da arquitetura Medallion.

---

## Justificativa

O AWS Glue oferece uma plataforma totalmente gerenciada para processamento distribuído utilizando Apache Spark, eliminando a necessidade de administrar clusters.

A solução integra-se de forma nativa ao Amazon S3 e ao AWS Glue Data Catalog, permitindo construir pipelines escaláveis para ingestão, transformação e disponibilização dos dados.

A utilização de uma única tecnologia para todas as etapas reduz a complexidade da arquitetura e facilita a manutenção da plataforma.

---

## Fluxo de Processamento

### Bronze Ingestion Job

Responsável por:

- consumir dados das APIs;
- validar respostas;
- registrar métricas da extração;
- persistir os dados brutos na camada Bronze.

---

### Silver Transformation Job

Responsável por:

- leitura da Bronze;
- limpeza e padronização dos dados;
- tratamento de nulos;
- deduplicação;
- enriquecimento;
- anonimização quando necessário;
- gravação da camada Silver.

---

### Gold Analytics Job

Responsável por:

- leitura da Silver;
- agregações;
- cálculo de KPIs;
- construção de datasets analíticos;
- disponibilização da camada Gold.

---

## Consequências

### Positivas

- utilização de uma única plataforma de processamento;
- processamento distribuído utilizando Apache Spark;
- integração nativa com Amazon S3 e Glue Catalog;
- redução da complexidade operacional;
- facilidade de escalabilidade;
- arquitetura aderente ao padrão Lakehouse.

### Negativas

- dependência do ecossistema AWS;
- maior tempo de inicialização dos Glue Jobs quando comparado ao AWS Lambda;
- custo superior ao Lambda para cargas pequenas.

---

## Alternativas Consideradas

### AWS Lambda

**Resultado:** Não selecionada.

**Vantagens**

- baixo tempo de inicialização;
- excelente para eventos.

**Desvantagens**

- limite de execução;
- inadequado para processamento analítico distribuído.

---

### Amazon EMR

**Resultado:** Não selecionada.

**Vantagens**

- controle total sobre o cluster Spark;
- maior flexibilidade.

**Desvantagens**

- maior esforço operacional;
- necessidade de gerenciamento da infraestrutura.

---

### Apache Airflow + Spark

**Resultado:** Não selecionada.

**Vantagens**

- elevada flexibilidade na orquestração.

**Desvantagens**

- maior complexidade de implantação;
- necessidade de administrar a infraestrutura.

---

### Amazon ECS/Fargate

**Resultado:** Não selecionada.

**Vantagens**

- execução de workloads containerizados.

**Desvantagens**

- maior complexidade para o cenário proposto;
- menor integração com o ecossistema analítico da AWS.

---

## Riscos

- aumento do tempo de execução conforme o volume de dados cresce;
- necessidade de otimizar particionamento e paralelismo dos jobs;
- custos adicionais em execuções frequentes.
