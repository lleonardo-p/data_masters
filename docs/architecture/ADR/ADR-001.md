# ADR-001: Escolha da Plataforma Cloud

- **Status:** Aceito
- **Data:** 2026-07-04
- **Decisores:** Leonardo Lucas Pereira

---

## Contexto

O BAIP (Brazil Arbovirus Intelligence Platform) é uma plataforma de Engenharia de Dados desenvolvida para demonstrar a construção de uma arquitetura moderna para monitoramento de arboviroses no Brasil.

A solução contempla processamento batch e streaming, arquitetura Lakehouse, Data Warehouse, processamento distribuído, observabilidade, governança de dados e disponibilização de indicadores analíticos.

Durante a definição da arquitetura, foram consideradas as seguintes alternativas de infraestrutura:

- Amazon Web Services (AWS)
- Microsoft Azure
- Google Cloud Platform (GCP)
- Infraestrutura On-Premises

Os principais requisitos considerados foram:

- baixo custo de implantação;
- utilização de serviços gerenciados;
- baixo esforço operacional;
- prazo reduzido de desenvolvimento;
- possibilidade de evolução da solução;
- escalabilidade e alta disponibilidade.

---

## Decisão

A plataforma será implementada utilizando **Amazon Web Services (AWS)**.

A solução será implantada em **uma única região AWS**, utilizando serviços gerenciados e recursos **Multi-AZ** sempre que suportados pelos serviços adotados.

Não será utilizada uma arquitetura multicloud.

---

## Justificativa

A AWS foi selecionada pelos seguintes motivos:

- disponibilidade do AWS Free Tier, reduzindo o custo do projeto;
- ampla oferta de serviços gerenciados voltados para Engenharia de Dados;
- integração nativa entre serviços como Amazon S3, AWS Glue, Amazon Athena, AWS Lambda, Amazon SQS e Amazon DynamoDB;
- menor complexidade operacional quando comparada a uma infraestrutura on-premises;
- experiência prévia com o ecossistema AWS, reduzindo a curva de aprendizado e permitindo maior foco no desenvolvimento da solução;
- prazo reduzido para implementação do projeto.

A adoção de uma arquitetura multicloud foi descartada por aumentar significativamente a complexidade da solução sem oferecer benefícios proporcionais ao escopo do projeto.

---

## Consequências

### Positivas

- redução do tempo de desenvolvimento;
- menor custo de implantação;
- utilização de serviços totalmente gerenciados;
- menor esforço operacional;
- arquitetura simplificada;
- facilidade de evolução e manutenção da plataforma.

### Negativas

- dependência do ecossistema AWS (*vendor lock-in*);
- menor portabilidade para outros provedores de nuvem;
- necessidade de adaptação da arquitetura em caso de migração para outra plataforma.

---

## Alternativas Consideradas

### Amazon Web Services (AWS)

**Resultado:** ✅ Selecionada

Atende aos requisitos funcionais e não funcionais do projeto, oferecendo serviços gerenciados, integração entre componentes e baixo custo inicial.

---

### Microsoft Azure

**Resultado:** Não selecionada

**Vantagens**

- forte integração com Power BI e Microsoft Fabric;
- ampla adoção no mercado corporativo.

**Desvantagens**

- maior curva de aprendizado para o contexto do projeto;
- aumento do tempo de implementação.

---

### Google Cloud Platform (GCP)

**Resultado:** Não selecionada

**Vantagens**

- plataforma analítica robusta;
- excelente integração com BigQuery.

**Desvantagens**

- necessidade de adaptação da arquitetura;
- maior curva de aprendizado.

---

### Infraestrutura On-Premises

**Resultado:** Não selecionada

**Vantagens**

- maior controle da infraestrutura;
- independência de provedor de nuvem.

**Desvantagens**

- maior custo operacional;
- necessidade de administração da infraestrutura;
- menor elasticidade;
- maior tempo de implantação.

---

## Riscos

- custos superiores ao esperado caso os recursos ultrapassem a camada gratuita;
- dependência de serviços específicos da AWS;
- necessidade de adaptações arquiteturais em uma eventual migração para outro provedor de nuvem.
