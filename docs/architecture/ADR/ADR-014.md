# ADR-014: Estratégia de Consumo Analítico e Dashboard

- **Status:** Aceito
- **Data:** 2026-07-05
- **Decisores:** Leonardo Lucas Pereira

---

## Contexto

O BAIP precisa disponibilizar indicadores epidemiológicos para análise e monitoramento das arboviroses no Brasil.

Os consumidores analíticos precisam visualizar:

- casos por município;
- casos por UF;
- evolução temporal;
- incidência por 100 mil habitantes;
- casos por doença;
- hospitalizações;
- infraestrutura de saúde;
- relação entre clima e casos;
- indicadores near real-time consolidados.

Foram consideradas as seguintes alternativas:

- Power BI;
- Amazon QuickSight;
- Streamlit;
- consultas diretas via Athena.

---

## Decisão

Será utilizado **Power BI** como ferramenta principal de dashboard analítico do BAIP.

O Power BI consumirá dados analíticos disponibilizados pelo Data Warehouse, preferencialmente por meio de consultas via Athena ou datasets exportados da camada Gold.

---

## Arquitetura Proposta

```text
Gold Data Lake
        │
        ▼
Data Warehouse
        │
        ▼
Amazon Athena
        │
        ▼
Power BI Dashboard
```

---

## Princípios de Consumo

O dashboard deverá consumir apenas dados analíticos e governados.

Regras:

- não consultar diretamente a Bronze;
- não consumir dados com PII;
- consumir preferencialmente a camada DW/Gold;
- utilizar tabelas fato e dimensão;
- apresentar indicadores agregados;
- evitar acoplamento direto com stores operacionais;
- não utilizar DynamoDB como fonte analítica principal.

---

## Indicadores Iniciais

O dashboard deverá apresentar:

- total de casos por doença;
- total de casos por UF;
- total de casos por município;
- evolução temporal dos casos;
- taxa de crescimento;
- hospitalizações;
- letalidade;
- incidência por 100 mil habitantes;
- casos versus precipitação;
- casos versus temperatura;
- infraestrutura hospitalar por região;
- indicadores near real-time consolidados.

---

## Justificativa

Power BI foi escolhido por ser amplamente utilizado no mercado corporativo, possuir boa capacidade de visualização e ser adequado para apresentação de portfólio.

Essa escolha permite:

- criação de dashboards interativos;
- facilidade de compartilhamento visual;
- boa aceitação em ambientes corporativos;
- integração com fontes SQL e dados tabulares;
- maior familiaridade para usuários de negócio.

Amazon QuickSight foi considerado por ser nativo AWS, mas Power BI oferece maior aderência ao objetivo de demonstrar uma solução de dados voltada a consumo analítico corporativo.

---

## Alternativas Consideradas

### Power BI

**Resultado:** Selecionado.

**Vantagens**

- forte adoção no mercado;
- boa experiência visual;
- adequado para dashboards executivos;
- fácil entendimento por usuários de negócio;
- bom para portfólio;
- integração com dados tabulares.

**Desvantagens**

- não é nativo da AWS;
- pode exigir configuração adicional para conexão;
- depende de licenciamento para compartilhamento corporativo.

---

### Amazon QuickSight

**Resultado:** Não selecionado como ferramenta principal.

**Vantagens**

- nativo AWS;
- integração com Athena;
- serviço gerenciado;
- adequado para dashboards em ambiente AWS.

**Desvantagens**

- menor adoção em algumas empresas brasileiras;
- menor familiaridade geral que Power BI;
- pode ter custo adicional dependendo do uso.

---

### Streamlit

**Resultado:** Não selecionado como dashboard principal.

**Vantagens**

- rápido para prototipar;
- bom para aplicações analíticas em Python;
- flexível para demos.

**Desvantagens**

- menos adequado para dashboard corporativo;
- exige hospedagem;
- maior esforço para governança e compartilhamento.

---

### Consultas Diretas via Athena

**Resultado:** Rejeitado como camada final de consumo.

**Vantagens**

- simples para usuários técnicos;
- permite exploração SQL.

**Desvantagens**

- não atende usuários de negócio;
- não oferece experiência visual;
- não substitui uma camada de BI.

---

## Consequências

### Positivas

- dashboards mais profissionais;
- facilidade de consumo por stakeholders;
- boa apresentação para portfólio;
- separação entre camada analítica e visualização;
- melhor comunicação dos indicadores.

### Negativas

- necessidade de modelar bem o DW;
- necessidade de configurar conexão ou exportação;
- possível dependência de licença para publicação.

---

## Riscos

- dashboards consumindo tabelas erradas;
- consultas pesadas e caras;
- exposição indevida de dados sensíveis;
- divergência entre KPIs e regras oficiais;
- acoplamento do dashboard à estrutura física do Data Lake.

---

## Mitigações

- consumo via tabelas Gold/DW;
- ausência de PII no modelo analítico;
- criação de views para KPIs;
- documentação dos indicadores;
- controle de acesso;
- revisão das consultas;
- padronização de nomenclatura.

---

## Decisão Final

O BAIP utilizará **Power BI** como ferramenta principal de dashboard analítico, consumindo dados governados da camada Gold/Data Warehouse.

Amazon QuickSight poderá ser considerado futuramente caso o objetivo seja manter toda a solução dentro do ecossistema AWS.
