# ADR-013: Estratégia de Orquestração dos Pipelines

- **Status:** Aceito
- **Data:** 2026-07-05
- **Decisores:** Leonardo Lucas Pereira

---

## Contexto

O BAIP possui diferentes pipelines de dados:

- ingestão batch de APIs públicas;
- transformação Bronze para Silver;
- transformação Silver para Gold;
- construção do Data Warehouse;
- validações de qualidade;
- sincronização near real-time com Gold;
- atualização de catálogo;
- geração de indicadores analíticos.

Esses processos precisam ser executados em ordem controlada, com tratamento de falhas, logs, reprocessamento e dependências explícitas.

Foram consideradas as seguintes alternativas:

- AWS Step Functions + EventBridge Scheduler;
- AWS Glue Workflows;
- Apache Airflow / MWAA;
- execução manual ou scripts isolados.

---

## Decisão

Será utilizada uma estratégia de orquestração baseada em **AWS Step Functions** combinada com **Amazon EventBridge Scheduler**.

O EventBridge Scheduler será responsável por disparar execuções programadas, enquanto o Step Functions coordenará as etapas do pipeline.

---

## Arquitetura Proposta

```text
EventBridge Scheduler
        │
        ▼
AWS Step Functions
        │
        ├── Bronze Ingestion Job
        ├── Silver Transformation Job
        ├── Data Quality Checks
        ├── Gold Analytics Job
        ├── Data Warehouse Builder Job
        └── Notification / Failure Handling
```

---

## Fluxo Batch Proposto

```text
Start
  │
  ▼
Bronze Ingestion
  │
  ▼
Silver Transformation
  │
  ▼
Data Quality Validation
  │
  ├── Success → Gold Analytics
  │
  └── Failure → Quarantine + Alert
  │
  ▼
Data Warehouse Builder
  │
  ▼
Update Catalog
  │
  ▼
End
```

---

## Fluxo Near Real-Time

O fluxo near real-time principal será orientado a eventos:

```text
Hospital SI → SQS → Lambda → DynamoDB
```

A sincronização dos indicadores near real-time com Gold poderá ser orquestrada por Step Functions em intervalos curtos.

---

## Justificativa

Step Functions foi escolhido por permitir orquestrar pipelines de dados e serviços AWS de forma gerenciada, visual e com controle de estado.

Essa abordagem permite:

- coordenar múltiplas etapas;
- controlar dependências;
- tratar falhas;
- realizar retries;
- registrar histórico de execução;
- reduzir necessidade de operar infraestrutura própria.

Airflow é uma excelente alternativa, mas adicionaria complexidade operacional para o escopo atual.

Glue Workflows é simples, mas menos flexível para orquestrar componentes além do Glue.

---

## Alternativas Consideradas

### AWS Step Functions + EventBridge Scheduler

**Resultado:** Selecionado.

**Vantagens**

- serviço gerenciado;
- bom controle de estado;
- integração com serviços AWS;
- suporte a retries e tratamento de falhas;
- visualização do fluxo;
- adequado para pipelines serverless;
- reduz esforço operacional.

**Desvantagens**

- pode ficar verboso para fluxos muito complexos;
- exige definição de state machines;
- menor flexibilidade que Airflow para DAGs muito sofisticadas.

---

### AWS Glue Workflows

**Resultado:** Não selecionado como orquestrador principal.

**Vantagens**

- integração direta com Glue Jobs;
- simples para pipelines Glue;
- baixa complexidade.

**Desvantagens**

- menos flexível para serviços fora do Glue;
- menor controle de fluxo;
- menos adequado para orquestrar Lambda, Athena, notificações e validações externas.

---

### Apache Airflow / MWAA

**Resultado:** Não selecionado para o MVP.

**Vantagens**

- padrão de mercado;
- excelente para DAGs complexas;
- grande ecossistema;
- boa flexibilidade.

**Desvantagens**

- maior complexidade operacional;
- maior custo;
- exige manutenção do ambiente;
- excesso para o escopo inicial.

---

### Execução Manual ou Scripts Isolados

**Resultado:** Rejeitado.

**Vantagens**

- simples no início.

**Desvantagens**

- baixa confiabilidade;
- difícil rastreabilidade;
- sem controle de dependências;
- alto risco operacional;
- não escalável.

---

## Consequências

### Positivas

- pipelines rastreáveis;
- controle de dependências;
- tratamento de falhas;
- integração com AWS;
- menor esforço operacional;
- arquitetura mais profissional.

### Negativas

- necessidade de manter state machines;
- aumento da complexidade inicial;
- possível custo adicional por execução.

---

## Riscos

- fluxos mal desenhados;
- falhas sem tratamento adequado;
- reprocessamentos inconsistentes;
- dependência excessiva da AWS;
- execução duplicada de pipelines.

---

## Mitigações

- uso de identificadores de execução;
- retries controlados;
- alarmes em falhas;
- logs estruturados;
- idempotência nos jobs;
- documentação dos fluxos;
- separação entre pipelines batch e near real-time.

---

## Decisão Final

O BAIP utilizará **AWS Step Functions** como orquestrador principal dos pipelines e **Amazon EventBridge Scheduler** para disparos programados.

Essa escolha oferece controle, rastreabilidade, baixo esforço operacional e boa integração com os serviços AWS adotados no projeto.
